## טעויות נפוצות ותיקונים

- **להריץ מתיקייה אחרת.** הפקודה נכשלת עם `No module named ch07`, כי הייבוא יחסי לתיקיית הפרויקט.
  מריצים תמיד מתוך `ai-course`, אחרי `cd` אליה.
- **לשכוח את הדגל `--env-file .env`.** ההרצה החיה נופלת על שגיאת אימות או על מפתח חסר, למרות
  שהמפתח קיים בקובץ. מוסיפים את הדגל לפקודה, כמו בצעד 4.
- **להעתיק את הבדיקות לתיקייה הלא נכונה.** הפקודה `uv run pytest -q` אוספת אפס בדיקות חדשות, או
  נכשלת על ייבוא. הקובץ שייך לתיקיית `tests` של הפרויקט, ליד בדיקות העשן של פרק 2.
- **לשלוח למודל רק את ההודעה האחרונה.** המודל „שוכח” את שמך כבר בסיבוב השני, גם בלי איפוס. הקריאה
  ב־`send` חייבת לקבל את כל מה ש־`to_steps` מחזיר, ואפשר לוודא ב־`/history` שההיסטוריה נשמרת.
- **סוג צעד אחד לכל הסיבובים.** הבדיקה הראשונה נכשלת כי היא מצפה לסירוגין של קלט משתמשת ופלט מודל.
  הסוג נקבע לפי התפקיד של כל סיבוב: `user_input` לתפקיד `user`, אחרת `model_output`.
- **שגיאת 429 במסלול החינמי באמצע שיחה.** התוכנית נופלת עם עקבות שגיאה, וההיסטוריה אובדת, כי אין
  עדיין טיפול בשגיאות (זה נושא פרק 11). ממתינים דקה ומתחילים שיחה חדשה; את מספרי הטוקנים שכבר
  ראית כדאי לרשום בפתק לפני כן.

## רמזים

1. `to_steps`: לכל סיבוב מילון אחד. הסוג `user_input` לתפקיד `user`, אחרת `model_output`. התוכן הוא
   רשימה עם בלוק טקסט אחד.
2. `cost_report`: הבדיקה דורשת ריווח קבוע: שישה תווים לערך הקלט, חמישה לערך הפלט וארבעה לחשיבה,
   עם עיצוב כמו `{value:>6}`. הפתרון מראה את הצורה המדויקת אם נתקעת על הריווח.
3. אם המודל „שוכח” גם בלי איפוס: בדקי ב־`/history` שההיסטוריה באמת נשמרת ושאת שולחת את
   `self.to_steps()` ולא רק את ההודעה האחרונה.
4. ההדגמה של מצב בצד השרת שולחת את הוראות המערכת גם בקריאה השנייה. זה לא שכפול מיותר: הן
   ברמת הבקשה, והשרת זוכר רק את ההיסטוריה.

## הפתרון

הקבצים בתיקייה `solution/` מכילים את המימוש המלא. **למה הוא עובד כך:** המחלקה `ChatBackend` מוגדרת
כ־`Protocol`, כלומר ממשק מבני: כל מחלקה שיש לה מתודת שליחה באותה חתימה מקיימת אותו, בלי ירושה.
לכן `Conversation` לא יודעת אם מולה Gemini או הלקוח המזויף של הבדיקות, וכל לוגיקת ההיסטוריה
והעלות נבדקת בלי רשת.

ההיסטוריה נשמרת כרשימת סיבובים פשוטה והופכת לצעדי API רק ברגע השליחה, כך שהקוד שולט בדיוק במה
שהמודל רואה. הסטטוס נבדק לפני שהטקסט נשמר, כדי שתשובה קטועה תסומן ולא תיראה כמו תשובה רגילה.

## מה התרגיל מדגים

- היסטוריה מפורשת: הקוד שולח את כל הסיבובים, ורואים את טוקני הקלט גדלים מסיבוב לסיבוב.
- הפרדה בין לוגיקת השיחה לבין הקריאה לרשת, דרך ממשק אחד ולקוח מזויף בבדיקות.
- קריאת סטטוס לפני שימוש בטקסט.
- מדידת עלות לכל סיבוב ולכל השיחה, ההרגל שחוזר בכל פרק מכאן והלאה.
- ההשוואה למצב בצד השרת: אותה שיחה, ושאלה אחת בלבד: מי שומר אותה ומה נשלח בכל בקשה.
