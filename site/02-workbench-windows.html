פרק 2: סביבת העבודה והקריאה הראשונה למודל

בסוף הפרק הזה יהיה לך מחשב מוכן לכל הקורס, ותוכנית Python אחת שמדברת עם מודל שפה אמיתי ומדפיסה את התשובה שלו, כמה טוקנים היא עלתה וכמה זמן לקחה. ההתקנות מינימליות ומכוונות: רק מה שמשרת את הקורס, כל צעד עם דרך לוודא שהוא הצליח, וטבלת תקלות בסוף. הפקודות כולן ל־PowerShell ב־Windows 11; אם את עובדת על Mac, סעיף 2.13 נותן את המקבילות, והשאר זהה.

הפרק מחולק לשני ימי לימוד, בכוונה. יום 0 (סעיפים 2.1 עד 2.4) הוא ההתקנות בלבד: הטרמינל, הכלים ו־Python. עשי אותו בסוף השבוע שלפני תחילת הקורס, בלי שעון, כי התקנות הן הצעד שהכי נוטה להשתבש כשהכלים חדשים, ואין סיבה שהן יחלקו יום עם הקריאה הראשונה למודל. יום 2 (סעיפים 2.5 עד 2.12) הוא הפרויקט, המפתח, הקריאה הראשונה והבדיקות. הקציבי ליום 0 בין שעה לשעה וחצי כולל הורדות, וליום 2 כשעה וחצי.

מה נלמד בפרק

  • מה מתקינים ולמה, ומה במכוון לא מתקינים.
  • לעבוד עם Windows Terminal ו־PowerShell 7, כולל הגדרה אחת שמונעת בעיות עם עברית.
  • להתקין Git, VS Code ו־uv באמצעות winget, ולנהל Python ותלויות עם uv בלבד.
  • להקים את פרויקט הקורס עם מבנה תיקיות קבוע.
  • להשיג מפתח API חינמי של Gemini, לשמור אותו נכון, ולא להדליף אותו לעולם.
  • להריץ קריאה ראשונה למודל ולקרוא את דיווח הטוקנים שלה.
  • לעצור, להפעיל מחדש ולנקות את כל מה שהתקנת.
  • מה שונה כשעובדים על Mac, בטבלה אחת.

ידע מקדים

פרקים 0 ו־1. היכרות בסיסית עם טרמינל כלשהו.

2.1 מה מתקינים, ומה לא

כלי מה הוא עושה בקורס איך מתקינים
Windows Terminal + PowerShell 7 הטרמינל שבו תריצי הכול. גרסה 7 תומכת ב־UTF-8 כברירת מחדל, וזה חשוב לעברית. מובנה ב־Windows 11; PowerShell 7 דרך winget
winget מנהל ההתקנות של Windows. פקודה אחת לכל כלי, קל לוודא ולהסיר. מובנה ב־Windows 11
Git ניהול גרסאות לפרויקט הקורס ולתיק העבודות, ובהמשך GitHub Actions. winget
VS Code העורך. אפשר במקומו Cursor, הכול זהה. winget
uv מנהל גרסאות Python, סביבות וירטואליות ותלויות, עם קובץ נעילה. מריץ סקריפטים בתוך הסביבה. winget
Python 3.12 מותקן דרך uv, לא מאתר python.org. uv python install 3.12
google-genai ה־SDK הרשמי של Gemini ל־Python. uv add
pytest, ruff בדיקות ובדיקת סגנון. uv add --dev

מה לא מתקינים, ולמה:

  • לא Python מהאתר הרשמי ולא Anaconda. uv מנהל גרסאות Python בעצמו, בלי להתנגש בשום דבר.
  • לא pip. uv מחליף אותו, ושומר קובץ נעילה.
  • לא Docker ולא WSL. לא נחוצים לקורס. אם את אוהבת לעבוד ב־WSL2 זה אפשרי, אבל אז כל הפקודות הופכות לפקודות Linux, והספר לא ילווה אותך בזה.
  • לא מסד נתונים חיצוני. נשתמש ב־SQLite המובנה ב־Python.

מונח: סביבה וירטואלית (virtual environment) היא תיקייה (.venv) שמכילה את Python ואת החבילות של פרויקט אחד, מבודדת מפרויקטים אחרים. קובץ הנעילה (uv.lock) מתעד את הגרסה המדויקת של כל חבילה שהותקנה, כך שהסביבה ניתנת לשחזור במחשב אחר. uv יוצר ומנהל את שניהם, ואת לעולם לא צריכה „להפעיל” את הסביבה ידנית: הפקודה uv run עושה זאת בשבילך.

2.2 הטרמינל: Windows Terminal ו־PowerShell 7

Windows 11 מגיע עם Windows Terminal. פתחי אותו (חפשי „Terminal” בתפריט התחל). ברירת המחדל שלו היא לרוב Windows PowerShell 5.1, הגרסה הישנה. נתקין את PowerShell 7 ונהפוך אותה לברירת המחדל:

winget install --id Microsoft.PowerShell -e --source winget

סגרי ופתחי מחדש את Windows Terminal. בהגדרות שלו (לחצי על החץ הקטן ליד הכרטיסיות, ואז Settings, ואז Startup, ואז Default profile) בחרי „PowerShell” בלי המילה Windows לפניו. פתחי כרטיסייה חדשה ובדקי:

$PSVersionTable.PSVersion

Major  Minor  Patch  PreReleaseLabel BuildLabel
-----  -----  -----  --------------- ----------
7      5      0

המספר הראשון צריך להיות 7. בספר, הפקודות מופיעות בלי התחילית PS C:\...> שאת רואה במסך, כדי שתוכלי להעתיק אותן כמו שהן. כמה פקודות שימושיות שחוזרות לאורך הספר:

פקודה מה היא עושה
pwd מדפיסה את התיקייה הנוכחית (זו הראשונה שבודקים כשמשהו „לא נמצא”)
cd <תיקייה> מעבר תיקייה; cd $HOME מחזיר לתיקיית המשתמשת
ls רשימת הקבצים בתיקייה
mkdir <שם> יצירת תיקייה
cat <קובץ> הדפסת תוכן קובץ
code . פתיחת התיקייה הנוכחית ב־VS Code
Ctrl+C עצירת תוכנית שרצה

הגדרה אחת לעברית, פעם אחת. Python ב־Windows מניח לעיתים קידוד ישן לפלט, ואז עברית מודפסת כסימני שאלה או שהתוכנית קורסת עם UnicodeEncodeError. הפתרון הקבוע הוא משתנה סביבה (environment variable) בשם PYTHONUTF8 עם הערך 1. משתנה סביבה הוא ערך בשם שהמערכת מעבירה לכל תוכנית שרצה; נשתמש במנגנון הזה גם למפתח ה־API. הגדירי אותו ברמת המשתמשת, פעם אחת:

[Environment]::SetEnvironmentVariable("PYTHONUTF8", "1", "User")

הפקודה לא מדפיסה דבר. סגרי ופתחי מחדש את הטרמינל: משתנה סביבה חדש נקלט רק בחלונות שנפתחו אחרי ההגדרה. בדיקה (אחרי שנתקין Python בסעיף 2.4):

uv run python -c "import sys; print(sys.flags.utf8_mode)"

2.3 התקנת Git, VS Code ו־uv

הריצי את שלוש הפקודות, אחת אחרי השנייה. כל התקנה לוקחת דקה או שתיים ועשויה לבקש אישור במסך:

winget install --id Git.Git -e --source winget
winget install --id Microsoft.VisualStudioCode -e --source winget
winget install --id=astral-sh.uv -e

סגרי ופתחי מחדש את הטרמינל (ההתקנות מוסיפות תיקיות ל־PATH, רשימת המקומות שבהם הטרמינל מחפש פקודות, והיא נקראת מחדש רק בחלון חדש). ודאי ששלושת הכלים עונים:

git --version
code --version
uv --version

git version 2.5x.x.windows.1
1.10x.x
...
uv 0.x.y (...)

המספרים המדויקים אצלך יהיו שונים; מה שחשוב הוא שאף פקודה לא מחזירה „is not recognized”. התקיני גם את תוסף Python של VS Code, מהטרמינל:

code --install-extension ms-python.python

ב־Windows: אם winget עצמו אינו מוכר, התקיני מחנות Microsoft את „App Installer” ונסי שוב. אם אין לך הרשאות ל־winget, אפשר להשתמש במתקין הרשמי של uv (הפקודה שלמטה), ואת Git ו־VS Code להוריד מאתריהם. עדכון של uv בעתיד נעשה בפקודה uv self update.

powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

הפקודה הראשונה מורידה Python 3.12 לתיקייה שמנוהלת על ידי uv, בלי לגעת בשום Python אחר במחשב. השנייה מציגה את הגרסאות המותקנות; ליד 3.12 צריך להופיע נתיב בתוך תיקיית uv. למה דווקא 3.12 ולא החדשה ביותר: כל הספריות בקורס מספקות עבורו חבילות מוכנות ל־Windows, וחלקן עדיין מפגרות בגרסאות חדשות יותר.

2.5 הקמת פרויקט הקורס

כל התרגילים בספר (פרט לפרויקט המסכם, שיקבל ריפו משלו בפרק 31) חיים בפרויקט אחד בשם ai-course בתיקיית המשתמשת. מבנה היעד:

C:\Users\<שם>\ai-course\
    pyproject.toml        הגדרות הפרויקט והתלויות
    .python-version       מצביע על 3.12
    uv.lock               גרסאות מדויקות של כל חבילה (נוצר אוטומטית)
    .venv\                הסביבה הווירטואלית (נוצרת אוטומטית, לא נכנסת ל-Git)
    .env                  המפתח שלך (לא נכנס ל-Git לעולם)
    .env.example          תבנית ללא סודות (כן נכנסת ל-Git)
    .gitignore
    README.md
    ch02\hello_model.py   התרגיל של הפרק
    tests\test_smoke.py   בדיקות עשן

הפקודות, מתוך הטרמינל:

cd $HOME
mkdir ai-course
cd ai-course
git init
uv init --bare --python 3.12
uv python pin 3.12
uv add "google-genai>=2.28,<3" pydantic
uv add --dev pytest ruff
uv run python --version

Python 3.12.x

מה כל פקודה עשתה:

פקודה מה היא עשתה
git init ריפו Git ריק
uv init --bare --python 3.12 קובץ הגדרות מינימלי (pyproject.toml), בלי קבצי דוגמה ובלי הגדרות אריזה
uv python pin 3.12 הקובץ .python-version, שמצמיד את הפרויקט ל־3.12 גם כשמותקנות גרסאות חדשות יותר
uv add ... הוספת התלויות לקובץ ההגדרות, פתרון הגרסאות לתוך uv.lock, יצירת .venv והתקנה
uv add --dev ... אותו דבר, לחבילות שנחוצות רק לפיתוח
uv run python --version הרצת ה־Python של הסביבה, בלי להפעיל אותה ידנית

הסיומת <3 בשם החבילה נועלת את ה־SDK לגרסאות 2.x: גרסה 3 הוכרזה עם שינויים שוברים, ואנחנו לא רוצות שהקוד בספר ישתנה מתחת לרגליים.

עכשיו צרי את קובץ .gitignore, שאומר ל־Git אילו קבצים לא לעקוב אחריהם. אפשר ב־VS Code (הפקודה code . פותחת את התיקייה), או ישירות מהטרמינל:

@"
.venv/
__pycache__/
*.py[oc]
.pytest_cache/
.ruff_cache/
.env
"@ | Set-Content .gitignore

השורה האחרונה היא החשובה ביותר: קובץ הסודות .env (סעיף 2.6) לא ייכנס ל־Git לעולם. צרי גם קובץ README.md עם שורה אחת שמתארת את הפרויקט.

פתחי את pyproject.toml והוסיפי בסופו את ההגדרה שמאפשרת לבדיקות למצוא את הקוד:

[tool.pytest.ini_options]
pythonpath = ["."]
testpaths = ["tests"]

ודאי שהקובץ מכיל שורות דומות לאלה (המספרים אצלך עשויים להיות גבוהים יותר):

2.6 מפתח ה־API: Google AI Studio

מפתח API (API key) הוא מחרוזת סודית שמזהה אותך מול שרתי Google ומשייכת אלייך כל קריאה. השגתו חינמית ואינה דורשת כרטיס אשראי:

  1. היכנסי לכתובת https://aistudio.google.com/apikey עם חשבון Google אישי (לא חשבון עבודה).
  2. לחצי „Create API key”. אם תתבקשי לבחור פרויקט, אשרי את ברירת המחדל; AI Studio יוצר פרויקט בשבילך.
  3. העתיקי את המפתח. הוא יוצג פעם אחת כמחרוזת ארוכה. אל תדביקי אותו בשום מקום חוץ מהקובץ שבצעד הבא.
  4. באותו אתר, בעמוד המגבלות, תראי את המגבלות של המסלול החינמי לכל מודל: בקשות לדקה ובקשות ליום. רשמי לעצמך את המספרים של gemini-3.5-flash-lite; נזדקק להם בפרק 11. כתובת העמוד: https://aistudio.google.com/rate-limit. התיעוד הרשמי לא מפרסם מספרים קבועים, ולכן המספרים שלך הם המקור.

עכשיו ניצור את קובץ הסודות. בתיקיית ai-course, צרי קובץ בשם .env (עם הנקודה בהתחלה) ובו שלוש שורות, כשבמקום PASTE_YOUR_KEY_HERE מודבק המפתח שלך:

GEMINI_API_KEY=PASTE_YOUR_KEY_HERE
MODEL_FAST=gemini-3.5-flash-lite
MODEL_SMART=gemini-3.8-flash

צרי גם קובץ .env.example עם אותן שורות אבל בלי המפתח (השאירי GEMINI_API_KEY= ריק): הוא ייכנס ל־Git ויסביר למי שמשכפל את הפרויקט אילו משתנים נדרשים. ולבסוף, ודאי ש־.env אכן מוחרג מ־Git:

git check-ignore .env

.env

אם הפקודה הדפיסה .env, הקובץ מוחרג. אם לא הדפיסה דבר, פתחי את .gitignore (סעיף 2.5) וודאי שיש בו שורה שמכילה בדיוק .env.

שימי לב: שלושה דברים על המפתח.

  • ה־SDK קורא את המפתח ממשתנה סביבה. השם הרגיל הוא GEMINI_API_KEY.
  • קיים גם שם חלופי, GOOGLE_API_KEY. אם שניהם מוגדרים, החלופי גובר. זה מקור לבלבול אם נשאר אצלך מפתח ישן מפרויקט אחר.
  • קובץ הסודות אינו נטען מעצמו. הדגל --env-file .env בפקודת ההרצה טוען אותו למשתני הסביבה של אותה הרצה בלבד. כך המפתח לא נשמר באופן קבוע במערכת ולא נכנס לקוד. בפרק 25 נראה את אותו מנגנון בשרת, עם הסודות של GitHub Actions.

מה שמות המודלים האלה: MODEL_FAST הוא המודל הזול והמהיר שישמש לרוב התרגילים, ו־MODEL_SMART הוא מודל חזק יותר להשוואות ולמשימות שדורשות איכות. שניהם במסלול החינמי נכון לאוקטובר 2026. Google משחררת מודלים חדשים כל כמה חודשים, ולכן השמות חיים בקובץ ההגדרות ולא בקוד: כשיתפרסם מודל חדש, תשני שורה אחת. העמוד https://ai.google.dev/gemini-api/docs/models מציג את הרשימה העדכנית.

2.7 הקריאה הראשונה: hello_model.py

צרי את התיקייה ch02 ובתוכה קובץ ריק __init__.py (הוא הופך את התיקייה לחבילה שהבדיקות יודעות לייבא) וקובץ hello_model.py עם התוכן הבא:

"""Chapter 2: the first call to a language model.

Run from the course root (the folder that contains pyproject.toml):

    uv run --env-file .env python ch02/hello_model.py

Prints the model's answer, the token usage reported by the API, the latency,
and what the call would have cost on the paid tier.
"""

from __future__ import annotations

import os
import sys
import time

from google import genai

# Paid-tier list prices per 1M tokens for the default fast model (checked 2026-10-03).
# On the free tier the real cost is 0; this is for building intuition only.
DEFAULT_PRICE_INPUT = 0.30
DEFAULT_PRICE_OUTPUT = 2.50


def estimate_paid_cost(
    input_tokens: int,
    output_tokens: int,
    price_input: float = DEFAULT_PRICE_INPUT,
    price_output: float = DEFAULT_PRICE_OUTPUT,
) -> float:
    """Return the price in USD for the given token counts at the given per-1M rates."""
    return (input_tokens * price_input + output_tokens * price_output) / 1_000_000


def require_api_key() -> None:
    if not (os.environ.get("GEMINI_API_KEY") or os.environ.get("GOOGLE_API_KEY")):
        sys.exit("No API key in the environment. Did you run with --env-file .env? See section 2.6.")


def main() -> None:
    require_api_key()
    model = os.environ.get("MODEL_FAST", "gemini-3.5-flash-lite")
    prompt = "הסבירי בשני משפטים, בעברית, מה עושה מודל שפה."

    client = genai.Client()  # reads GEMINI_API_KEY / GOOGLE_API_KEY from the environment
    started = time.perf_counter()
    # No try/except on purpose: if the key, the model name or the rate limit is wrong,
    # the traceback's last line says exactly what happened. Chapter 11 adds real error handling.
    interaction = client.interactions.create(model=model, input=prompt)
    elapsed = time.perf_counter() - started

    usage = interaction.usage
    input_tokens = (usage.total_input_tokens if usage else None) or 0
    output_tokens = (usage.total_output_tokens if usage else None) or 0
    thought_tokens = (usage.total_thought_tokens if usage else None) or 0

    print(interaction.output_text)
    print("-" * 40)
    print(f"model:           {model}")
    print(f"input tokens:    {input_tokens}")
    print(f"output tokens:   {output_tokens}")
    print(f"thought tokens:  {thought_tokens}")
    print(f"latency:         {elapsed:.2f} s")
    print(f"paid-tier price: ${estimate_paid_cost(input_tokens, output_tokens):.6f} (free tier: $0)")


if __name__ == "__main__":
    main()

שימי לב לארבעה דברים בקוד, כי הם יחזרו בכל פרק:

  1. הלקוח (client). האובייקט שמייצג את החיבור לשירות נוצר בשורה client = genai.Client(). הוא מוצא את המפתח במשתני הסביבה בעצמו; לעולם לא נעביר לו מפתח כמחרוזת בקוד.
  2. הקריאה. הפונקציה create שולחת בקשה אחת ומחזירה אובייקט אינטראקציה (interaction). הטקסט שהמודל יצר נמצא בשדה output_text. בפרק 7 נפתח את כל השדות האחרים: רשימת הצעדים, המזהה שמאפשר להמשיך שיחה, ועוד.
  3. דיווח השימוש (usage). השירות מחזיר כמה טוקנים נכנסו, כמה יצאו, וכמה שימשו ל„חשיבה” (במודל המהיר זה בדרך כלל אפס). טוקן הוא יחידת הטקסט שהמודל עובד איתה, בערך שלושה רבעים ממילה באנגלית ופחות מזה בעברית; פרק 5 מסביר. התשלום אצל כל הספקים נקבע לפי המספרים האלה, ולכן נדפיס אותם בכל תרגיל. שמות השדות המדויקים מופיעים בקוד למעלה.
  4. שגיאות. בכוונה אין כאן try/except. אם המפתח שגוי, שם המודל לא קיים או שחרגת ממגבלת הקצב, Python יציג traceback, והשורה האחרונה שלו אומרת בדיוק מה קרה: שם מחלקת השגיאה (למשל RateLimitError כשחורגים ממגבלת הקצב, קוד 429) וההודעה מהשרת. לקרוא את השורה האחרונה של traceback היא המיומנות שצריך עכשיו, וטבלת התקלות בסעיף 2.11 ממפה את השורות הנפוצות. בפרק 11 נבנה שכבת טיפול בשגיאות אמיתית, שמחליטה מה מנסים שוב ומה לא.
