# פרק 25: פריסה ותזמון

עיתון בוקר שצריך להריץ ביד הוא לא עיתון בוקר. הפרק הופך את הקוד למשימה שרצה בלי אדם: קונפיגורציה
לפי סביבה, GitHub Actions עם תזמון (ועם המלכודת של שעון קיץ), סודות, תוצרים (artifacts) והפעלה ידנית;
CI שמריץ את הבדיקות הלא־מקוונות ואת ההערכות המהירות לפני כל ריצה בתשלום; גרסאות של הנחיה, מודל
ואינדקס יחד, ומה זה „חזרה לאחור” כשאחד מהם הוא מודל אצל ספק; וחלופה מקומית ב־Windows Task
Scheduler. בסופו ריצה מתוזמנת תייצר קובץ Markdown ודוח ריצה ב־GitHub בלי שתגעי במקלדת.

## מה נלמד בפרק

- קונפיגורציה וסביבות: מה בקובץ, מה במשתנה סביבה, מה בסוד.
- GitHub Actions: cron ב־UTC, שעון קיץ, סודות, תוצרים, הפעלה ידנית.
- CI לפני ריצה: בדיקות לא־מקוונות והערכות מהירות.
- גרסאות יחד: הנחיה, מודל, אינדקס, סכמה.
- חזרה לאחור ורעיון הקנרית.
- Windows Task Scheduler כחלופה; Docker כתיבה אופציונלית.

## ידע מקדים

פרק 18 (המדרגות וה־CI), פרק 22 (המעקב), פרק 23 (שומר התקציב). התרגיל דורש מאגר GitHub.

## 25.1 קונפיגורציה וסביבות

| סוג | דוגמה | איפה | למה |
| --- | --- | --- | --- |
| קוד | הלוגיקה | Git | משתנה בגרסאות |
| הגדרה | מספר פריטים, שפה, נושאים | קובץ בגיט (`profile.yaml`) | שונה בין משתמשות, לא סודי, מגורסן |
| סביבה | שמות מודלים, נתיבים | משתני סביבה, או קובץ `.env` מקומי | שונה בין מכונה ל־CI |
| סוד | מפתח API, סיסמת מייל | `.env` מקומי (לא בגיט); GitHub Secrets ב־CI | אסור שיהיה בקוד או בלוג |
| גרסאות | הנחיה, מודל, אינדקס | `versions.json` בגיט | סעיף 25.4 |

הכלל: קוד אחד, קונפיגורציה לכל סביבה, סודות מחוץ לגיט. אותו `daily_job.py` רץ על המחשב שלך
(`.env`), ב־CI (secrets), ובמכולה (משתני סביבה).

## 25.2 GitHub Actions: המשימה שרצה בלי אדם

ה־workflow בתרגיל (`daily.yml`) מכיל כל מה שמשימה מתוזמנת צריכה:

<div dir="ltr" align="left">

```yaml
on:
  schedule:
    - cron: "0 4 * * *"     # summer: 07:00 Asia/Jerusalem is 04:00 UTC
    - cron: "0 5 * * *"     # winter: 05:00 UTC
  workflow_dispatch:        # the "run it now" button
    inputs: { items: { default: "5" } }
```

</div>

**המלכודת של שעון הקיץ.** cron ב־GitHub Actions רץ ב־UTC ולא יודע מה זה שעון קיץ. 07:00
בירושלים הוא 04:00 UTC בקיץ (UTC+3) ו־05:00 UTC בחורף (UTC+2). פתרון של שורה אחת ייתן עיתון ב־06:00
או ב־08:00 במחצית השנה. הפתרון בתרגיל: **שתי שורות cron, והמשימה בודקת בעצמה** (`--local-hour 7`)
אם עכשיו שבע בירושלים; אם לא, היא יוצאת עם קוד 2 בלי לעשות כלום, וה־workflow מתייחס לזה כהצלחה
שקטה. `cron_for_local_time` מחשב את שתי השורות מתוך `zoneinfo`, לכל אזור זמן.

**סודות.** `GEMINI_API_KEY: ${{ secrets.GEMINI_API_KEY }}` נכנס כמשתנה סביבה; GitHub ממסך אותו
בלוגים. בלי הסוד, המדרגה המהירה עדיין רצה (היא לא צריכה מפתח), והמשימה נכשלת מוקדם וברור.

**תוצרים.** `upload-artifact` שומר את `brief-<date>.md`, `run-report.json` ו־`traces.jsonl` ל־14 יום.
זה המקום שבו רואים את העיתון של הבוקר בלי מחשב דולק. `if: always()` מעלה את התוצרים גם כשהריצה
נכשלה: הדוח של ריצה שנכשלה הוא החשוב מכולם.

**הפעלה ידנית.** `workflow_dispatch` עם קלט (`items`) הוא כפתור „הרץ עכשיו” לבדיקה אחרי שינוי.

## 25.3 CI לפני ריצה בתשלום

הצעד הראשון ב־workflow הוא `uv run pytest -q -m "not judge"`: המדרגה המהירה של פרק 18, בלי
מפתח. אם היא אדומה, המשימה לא רצה, ולא משלמים על ריצה של קוד שבור. ההערכות עם השופט לא רצות
כאן (איטיות ובתשלום); הן רצות בלילה אחר, ב־workflow של פרק 18. **סדר העבודה:** בדיקות, ואז ריצה,
ואז תוצרים. ואם הריצה נכשלה, הדוח עולה בכל זאת.

## 25.4 גרסאות יחד

במערכת רגילה, גרסה היא commit. במערכת מודל, ההתנהגות תלויה בארבעה דברים שמשתנים בנפרד:

| רכיב | משתנה כש… | מי שולט |
| --- | --- | --- |
| הנחיה (`summarize.v3`) | עורכים קובץ | את |
| מודל (`gemini-3.5-flash-lite`) | הספק מעדכן, או את מחליפה | שניכם |
| אינדקס (`notes-2026-10`) | מאנדקסים מחדש, או משנים מודל שיכון | את |
| סכמה (`schema_version: 1`) | משנים את `ArticleSummary` | את |

`versions.json` מצהיר על ארבעתם במקום אחד, ו־`check_versions` משווה אותם למציאות לפני הריצה:
קובץ ההנחיה קיים? משתני הסביבה של המודלים תואמים? האינדקס נבנה עם מודל השיכון המוצהר? אי־התאמה
היא כישלון מוקדם, לא עיתון מוזר. ואז **חזרה לאחור** (rollback) היא פעולה מוגדרת: לשחזר את
`versions.json` הקודם (ואת האינדקס שהוא מצביע עליו), לא „לבטל את העריכה של ההנחיה” בלבד, כי
ההנחיה החדשה אולי נמדדה מול המודל החדש.

מה שלא נשלט: הספק יכול לשנות את התנהגות המודל מתחת לאותו שם. ההגנה היא ההערכה שרצה בלילה
(פרק 18): ציון שיורד בלי שינוי אצלך פירושו שהמודל זז.

## 25.5 הקנרית

כשמשנים הנחיה או מודל, לא מחליפים את כל העיתון בבת אחת. **קנרית** (canary) היא ריצה אחת של
הגרסה החדשה לצד הישנה: אותם פריטים, שני סיכומים, ההערכה והקוראת משוות, ורק אז מחליפים. בפרויקט
זה `--versions versions-next.json` לריצה ידנית, והשוואת שני הדוחות (פרק 16). עבור מערכת של אדם
אחד, זה מספיק; במערכת גדולה, אחוז מהתעבורה.

## 25.6 המשימה עצמה

`daily_job.py` הוא מה שה־workflow מריץ, והוא נבנה לרוץ בלי אדם:

| תכונה | איך |
| --- | --- |
| קודי יציאה ברורים | 0 הצלחה, 2 דילוג (לא השעה), 3 המודל נכשל על הכול, 4 התקציב נגמר |
| תוצרים תמיד | `brief-<date>.md` ו־`run-report.json`; הדוח נכתב גם בכישלון |
| מעקב | `TracingClient` של פרק 22 לכל קריאה; `traces.jsonl` עולה כתוצר |
| תקציב | `BudgetGuard` של פרק 23; חריגה כותבת דוח ויוצאת 4 |
| כשל חלקי | פריט שנכשל נספר ונרשם; הריצה ממשיכה |
| הרצה יבשה | `--dry-run` עם `FakeClient`: אותו קוד, בלי מפתח, ל־CI ולבדיקות |
| גרסאות | קורא `versions.json` אם קיים; המודל משם |

`--dry-run` הוא מה שמאפשר לבדוק את *כל* המשימה בלי רשת: הבדיקה מריצה אותה על שלושה פריטים
מזויפים ובודקת את הקובץ, את הדוח ואת המעקב. ההרצה האמיתית שונה רק בלקוח.

## 25.7 Windows Task Scheduler

GitHub Actions דורש מאגר ורשת. על המחשב עצמו, Task Scheduler עושה את אותו דבר, בזמן מקומי
(בלי המלכודת של UTC):

<div dir="ltr" align="left">

```powershell
schtasks /Create /TN "MorningBrief" /SC DAILY /ST 07:00 /TR "pwsh -File C:\path\to\ai-course\run_daily.ps1" /F
schtasks /Run /TN "MorningBrief"
schtasks /Query /TN "MorningBrief" /V /FO LIST
```

</div>

`run_daily.ps1` עובר לתיקיית הפרויקט, מריץ את המשימה עם `--env-file .env`, ומנתב את הפלט לקובץ
לוג יומי. ההבדל מ־CI: המחשב צריך להיות דלוק, והסודות הם `.env` המקומי. בשביל עיתון אישי זה
לגיטימי לגמרי, וזה מה שתעשי אם אין לך מאגר ציבורי.

## 25.8 תיבה אופציונלית: Docker

מכולה היא „אותה סביבה בכל מקום”: Python, התלויות והקוד בתמונה אחת, המפתח כמשתנה סביבה בזמן
ריצה. ה־`Dockerfile` בתרגיל הוא עשר שורות עם `uv sync --frozen`. מתי זה שווה: כשהמשימה רצה על
שרת שאינו שלך, או כשצריך גרסת Python מסוימת. מתי לא: לעיתון אישי על המחשב או ב־Actions, `uv`
לבד מספיק.

## סיכום

- קוד אחד, קונפיגורציה לכל סביבה, סודות מחוץ לגיט, גרסאות בקובץ אחד.
- cron ב־UTC בלי שעון קיץ: שתי שורות, והמשימה בודקת את השעה המקומית.
- סודות של המאגר, תוצרים גם בכישלון, כפתור הפעלה ידנית.
- בדיקות לא־מקוונות לפני כל ריצה בתשלום; השופט בלילה אחר.
- הנחיה, מודל, אינדקס וסכמה מגורסנים יחד; חזרה לאחור משחזרת את הקובץ; קנרית לפני החלפה.
- קודי יציאה, דוח תמיד, הרצה יבשה; Task Scheduler בזמן מקומי; Docker כשצריך.

## מונחים לזכור

| מונח בעברית | באנגלית | במשפט אחד |
| --- | --- | --- |
| משימה מתוזמנת | scheduled job | קוד שרץ בזמן קבוע בלי אדם |
| cron | cron | תחביר של תזמון: דקה שעה יום חודש יום־בשבוע, ב־UTC ב־Actions |
| שעון קיץ | daylight saving time (DST) | הסיבה שלשעה מקומית יש שני זמני UTC בשנה |
| סוד | secret | ערך שמוזרק כמשתנה סביבה ולא מופיע בקוד או בלוג |
| תוצר | artifact | קובץ שנשמר מריצה: העיתון, הדוח, המעקב |
| הפעלה ידנית | workflow_dispatch | כפתור „הרץ עכשיו” עם קלטים |

| חזרה לאחור | rollback | שחזור של קובץ הגרסאות והאינדקס שהוא מצביע עליו |
| קנרית | canary | ריצה אחת של גרסה חדשה לצד הישנה, לפני החלפה |
| הרצה יבשה | dry run | אותו קוד עם לקוח מזויף; בלי רשת ובלי מפתח |

## טעויות נפוצות

- **שורת cron אחת.** העיתון זז בשעה פעמיים בשנה.
- **המפתח בקובץ ה־workflow.** סוד של המאגר, או כלום.
- **תוצרים רק בהצלחה.** הדוח של הכישלון הוא זה שצריך.
- **ריצה בתשלום בלי בדיקות לפניה.** משלמים על קוד שבור.
- **לגרסן רק את ההנחיה.** ההנחיה נמדדה מול מודל ואינדקס מסוימים.
- **להחליף מודל בלי קנרית.** עיתון שלם ברמה לא ידועה.
- **קוד יציאה אפס תמיד.** אף אחד לא יודע שהמשימה דילגה או נכשלה.

## שאלות ראיון

1. **איך את פורסת משימת מודל שרצה כל בוקר?** GitHub Actions עם cron, שתי שורות בגלל שעון הקיץ
   והמשימה בודקת את השעה המקומית; המפתח כסוד; בדיקות לא־מקוונות לפני הריצה; תוצרים (העיתון, דוח
   ריצה, מעקב) גם בכישלון; קודי יציאה ברורים ותקציב. ואותו קוד רץ מקומית עם Task Scheduler.
2. **מה הגרסה של מערכת מודל?** לא commit בלבד: הנחיה, מודל, אינדקס וסכמה יחד, בקובץ אחד שנבדק מול
   המציאות בתחילת הריצה. חזרה לאחור משחזרת את הקובץ ואת האינדקס. ומה שהספק משנה מתחת לשם
   המודל נתפס רק בהערכה שרצה בקביעות.
3. **מה המלכודת של cron ב־Actions?** הוא ב־UTC ובלי שעון קיץ; שעה מקומית קבועה היא שני זמני UTC
   בשנה. פתרון: שתי שורות ובדיקה בתוך המשימה, או קבלת סחף של שעה.
4. **איך משנים הנחיה בייצור בלי לשבור את העיתון?** גרסה חדשה בקובץ נפרד, ריצת קנרית לצד הישנה
   על אותם פריטים, השוואה בהערכה ובעין, ואז החלפה של קובץ הגרסאות עם דרך חזרה.

- הריצה המתוזמנת הבאה ייצרה תוצר בעצמה (או דילגה עם קוד 2 בשעה הלא נכונה, ורואים את זה בלוג).
