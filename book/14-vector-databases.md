# פרק 14: מאגרי וקטורים

בשני הפרקים הקודמים כל הווקטורים חיו במטריצת numpy בזיכרון, וזה עבד מצוין. הפרק הזה מתחיל בשאלה
הפוכה מהמקובל: **מה בעצם חסר?** התשובה היא לא „מהירות”, לפחות לא בגדלים שלנו; היא התמדה, סינון
לפי מטא־נתונים, עדכון לפי מזהה, ועבודה מכמה תהליכים. „מאגר וקטורים” (vector database) הוא
התוכנה שנותנת את אלה מעל אינדקס של שכנים קרובים. נלמד את Chroma, המאגר המוטמע של הקורס, את
הנוף סביבו, מתי לא צריך אותו בכלל, ואת ההרגל התפעולי החשוב ביותר: אינדוקס מחדש כשהמודל משתנה.
בסופו האינדקס של הכותרות יחיה על הדיסק, עם מסנן תאריך, ויסרב לערבב וקטורים משני מודלים.

## מה נלמד בפרק

- מה numpy כבר נותן, ומה מאגר וקטורים מוסיף.
- המבנה: אוספים, מזהים, וקטורים, מסמכים, מטא־נתונים, מרחקים.
- Chroma בפועל: לקוח מתמיד, upsert, שאילתה עם מסננים, מחיקה.
- אינדוקס מחדש כשהמודל משתנה, ולמה המאגר צריך לסרב לערבב.
- הנוף: numpy, sqlite-vec, pgvector, Qdrant, Weaviate, Pinecone, FAISS.
- מבחן „האם numpy מספיק?”.
- תפעול: גיבוי, גרסאות, הרשאות כמטא־נתונים מול אכיפה בקוד, מחיקה.

## ידע מקדים

פרקים 12 ו־13. התרגיל קורא ל־API (שיכונים; המטמון מפרק 12 חוסך את רובן).

## 14.1 מה numpy נותן, ומה חסר

סריקה מלאה של מטריצה בגודל 100 אלף על 768 היא עשרות אלפיות שנייה. בגדלים של רוב הפרויקטים
הפנימיים, המהירות לא הסיבה לעבור למאגר. מה כן:

| צורך | numpy | מאגר וקטורים |
| --- | --- | --- |
| התמדה | שומרים קובץ `.npy` ועוד קובץ של מזהים, ומנהלים את הקשר ביניהם ביד | חלק מהמאגר |
| סינון לפי מטא־נתונים | מסננים אחרי החיפוש, ומקווים שנשארו תוצאות | מסנן בתוך השאילתה: „רק מהשבוע האחרון” |
| עדכון לפי מזהה | מוצאים את השורה, מחליפים, שומרים הכול מחדש | `upsert` |
| מחיקה | אותו דבר | `delete` לפי מזהה או מסנן |
| מיליוני וקטורים | סריקה מלאה נהיית איטית | אינדקס ANN (פרק 13) |
| כמה תהליכים או שירותים | נעילות ביד | המאגר מטפל |
| כמה אוספים | כמה מטריצות וכמה רשימות | אוספים עם שמות |

הטור הימני הוא בדיוק מה שהפרויקט צריך לזיכרון בין ימים: שמירה בין הרצות, „רק סיפורים מ־60 הימים
האחרונים”, והוספה של כותרות היום בלי לבנות הכול מחדש. לכפילויות *באותו יום*, לעומת זאת, numpy
מספיק, והפרויקט ישאיר את זה כך.

## 14.2 המבנה

כל מאגרי הווקטורים חולקים אוצר מילים:

- **אוסף** (collection): טבלה. לכל אוסף מודל שיכון אחד ומרחק אחד.
- **מזהה** (id): מחרוזת ייחודית לפריט. בחירה טובה היא משהו יציב ומשמעותי: מזהה הכותרת, גיבוב
  התוכן.
- **וקטור** (embedding): המספרים. או שאנחנו מחשבים אותם ושולחים, או שהמאגר קורא למודל בשבילנו.
- **מסמך** (document): הטקסט המקורי, כדי שלא נצטרך לשמור אותו במקום אחר.
- **מטא־נתונים** (metadata): מילון שטוח של מחרוזות, מספרים ובוליאנים: מקור, תאריך, נושא. זה מה
  שמסננים לפיו.
- **מרחק** (distance): איך משווים. קוסינוס לשיכונים מנורמלים; אוקלידי (L2) או מכפלה פנימית
  במקרים אחרים. Chroma מחזירה *מרחק* קוסינוס, שהוא 1 פחות הדמיון, אז 0 הוא זהה ו־1 הוא ניצב.

## 14.3 Chroma בפועל

Chroma היא מאגר מוטמע: ספריית פייתון שכותבת לתיקייה, בלי שרת, עם גלגלי Windows. התרגיל עוטף
אותה במחלקה אחת, `HeadlineStore`; אלה הקריאות שבפנים:

<div dir="ltr" align="left">

```python
import chromadb
from chromadb.config import Settings

client = chromadb.PersistentClient(path="ch14/chroma", settings=Settings(anonymized_telemetry=False))
collection = client.get_or_create_collection(
    "headlines",
    metadata={"hnsw:space": "cosine", "embedding_model": "gemini-embedding-2"},
)

collection.upsert(
    ids=["h042", "h043"],
    embeddings=vectors.tolist(),               # we computed and normalized them (chapter 12)
    documents=["Kubernetes 1.36 upgrade breaks ...", "Python 3.14 released ..."],
    metadatas=[{"source": "cloudbeat", "day": 20260925}, {"source": "hn", "day": 20260912}],
)

result = collection.query(
    query_embeddings=embedder.embed(["kubernetes upgrade broke networking"]).tolist(),
    n_results=5,
    where={"$and": [{"day": {"$gte": 20260920}}, {"source": "hn"}]},
    include=["documents", "distances", "metadatas"],
)
ids, distances = result["ids"][0], result["distances"][0]   # similarity = 1 - distance
```

</div>

הערות שחוסכות שעה כל אחת:

- **שם האוסף** חייב להיות באורך 3 עד 512 תווים, אותיות לטיניות, ספרות, נקודה, קו תחתון ומקף.
- **`hnsw:space`** נקבע ביצירה ולא ניתן לשינוי. ברירת המחדל היא L2; לשיכונים רוצים `cosine`.
- **תאריכים כמספרים.** המסננים `$gt`, `$gte`, `$lt`, `$lte` עובדים על מספרים בלבד; מחרוזת
  „2026-09-20” נדחית. לכן `day` הוא מספר שלם בצורת yyyymmdd, שמסתדר נכון בהשוואה.
- **מסננים מרובים** עוטפים ב־`$and` או `$or`; מסנן אחד נשלח כמו שהוא.
- **`n_results` גדול מהאוסף** זורק שגיאה בחלק מהגרסאות; מצמצמים ל־`min(k, count)`.
- **`upsert` לפי מזהה קיים מחליף** את הווקטור, המסמך והמטא־נתונים. זה מה שהופך הרצה חוזרת
  לבטוחה.
- **פונקציות שיכון מובנות.** Chroma יכולה לקרוא למודל שיכון בעצמה אם לא שולחים וקטורים. ברירת
  המחדל שלה מורידה מודל מקומי קטן בפעם הראשונה. אנחנו שולחים וקטורים בעצמנו, כדי שהמודל, הנרמול
  והמטמון יהיו של פרק 12 ולא של המאגר.
- **טלמטריה.** ברירת המחדל שולחת נתוני שימוש אנונימיים; `anonymized_telemetry=False` מכבה.

## 14.4 אינדוקס מחדש כשהמודל משתנה

וקטור מ־`gemini-embedding-2` ב־768 ממדים ווקטור מאותו מודל ב־256 ממדים, או ממודל אחר, אינם
ניתנים להשוואה (פרק 12). אוסף שמכיל את שניהם מחזיר תוצאות שנראות סבירות ושגויות. זה הבאג
הכי שקט במאגרי וקטורים, ולכן `HeadlineStore` שומר את **שם המודל במטא־נתונים של האוסף** ובודק
אותו בפתיחה:

<div dir="ltr" align="left">

```python
store = HeadlineStore(path, embedder)
if store.needs_reindex():        # collection metadata says another model built it
    store.reindex(items)         # delete the collection, recreate, upsert everything
store.upsert(items)              # refuses (RuntimeError) while the models differ
```

</div>

אינדוקס מחדש של 200 כותרות הוא שניות; של מיליון מסמכים הוא שעות ועלות API. בפריסה אמיתית
בונים אוסף **חדש** בשם עם גרסה (`headlines_v2`), ממלאים אותו ברקע, ומחליפים את השם שהקוד קורא
לו כשהוא מוכן. אותו עיקרון: וקטורים משני מודלים לא פוגשים זה את זה באותו אוסף, לעולם.

## 14.5 הנוף

| כלי | במשפט | מתי |
| --- | --- | --- |
| numpy | מטריצה בזיכרון וסריקה מלאה | עד מאות אלפי וקטורים, תהליך אחד, בלי מסננים מורכבים |
| sqlite-vec | הרחבה ל־SQLite עם חיפוש וקטורי | כשהנתונים כבר ב־SQLite ורוצים קובץ אחד |
| Chroma | מאגר מוטמע, אוספים, מסננים, HNSW | פרויקטים אישיים וקטנים, אב־טיפוס, הקורס הזה |
| pgvector | הרחבה ל־PostgreSQL | כשיש כבר Postgres: וקטורים ליד הנתונים, טרנזקציות, הרשאות של מסד |
| Qdrant, Weaviate | שרתים ייעודיים, קוד פתוח | מיליונים ומעלה, מסננים כבדים, כמה שירותים |
| Pinecone | שירות מנוהל | כשלא רוצים לתפעל כלום ומוכנים לשלם |
| FAISS | ספריית אינדקסים (Meta) | מחקר, שליטה מלאה באלגוריתם, בלי התמדה ומטא־נתונים |

הטיה שכדאי לדעת עליה: הרבה חומר שיווקי מדבר על מיליארדי וקטורים. רוב המערכות הפנימיות הן
עשרות אלפים. בחירת כלי צריכה להתחיל מהגודל האמיתי, לא מהגודל שאולי יהיה.

## 14.6 מבחן „האם numpy מספיק?”

לפני שמוסיפים תלות, חמש שאלות. אם התשובה לכולן היא „לא”, numpy מספיק:

| שאלה | אם „כן” |
| --- | --- |
| יותר ממאות אלפי וקטורים, או שאילתות רבות לשנייה? | צריך ANN |
| צריך לשמור בין הרצות בלי לנהל קבצים ביד? | צריך התמדה |
| מסננים לפי מטא־נתונים לפני החיפוש (תאריך, מקור, משתמשת)? | צריך מסננים באינדקס |
| כמה תהליכים או שירותים כותבים וקוראים? | צריך מאגר, ואולי שרת |
| מחיקות ועדכונים תכופים לפי מזהה? | צריך upsert ו־delete |

בפרויקט: כפילויות באותו יום, „לא” לכולן, numpy. זיכרון בין ימים, „כן” להתמדה ולמסננים, Chroma.
ההערה הזאת נכנסת למסמך ההחלטות של הפרויקט כפי שהיא.

## 14.7 תפעול

- **גיבוי.** Chroma היא תיקייה; גיבוי הוא העתקה כשהתהליך לא כותב. המטמון של השיכונים (פרק 12)
  הוא הביטוח האמיתי: אפשר לבנות הכול מחדש בלי קריאות API.
- **גרסאות.** שם המודל במטא־נתונים של האוסף (14.4); שם אוסף עם גרסה כשמחליפים.
- **הרשאות.** מסנן `where={"owner": user}` **אינו גבול אבטחה**; הוא מסנן שהקוד *בוחר* להפעיל. אם
  שאילתה אחת שוכחת אותו, המשתמשת רואה הכול. הרשאות אמיתיות נאכפות בקוד שעוטף את המאגר, או
  במאגר שתומך בהן (pgvector יורש את ההרשאות של Postgres). במאגר מוטמע: אוסף נפרד לכל דייר כשזה
  חשוב.
- **נתונים אישיים.** המסמך נשמר כטקסט במאגר; הווקטור ניתן להיפוך (פרק 12). שניהם רגישים כמו
  המקור, ו„זכות להישכח” פירושה `delete` לפי מזהה או מסנן, בכל האוספים.
- **שימור** (retention). „60 ימים” הוא `delete(where={"day": {"$lt": cutoff}})` שרץ בסוף כל הרצה.
  פשוט, אם `day` הוא מספר.

## 14.8 בפרויקט

- **אוסף `story_memory`:** וקטור של כותרת ושורת פתיחה; מטא־נתונים `{day, cluster_id, url}`;
  שימור 60 ימים.
- **שאילתת ההמשכים:** לכל סיפור של היום, חיפוש באוסף עם `day` בטווח של השבועיים האחרונים; דמיון
  מעל סף פירושו „המשך לסיפור מתאריך X”, והעיתון מציין את זה.
- **כפילויות באותו יום** נשארות ב־numpy.
- **אותו מודל, אותו מטמון**, אותו `embedding_model` במטא־נתונים; החלפת מודל היא אינדוקס מחדש
  מתוכנן.

## סיכום

- מאגר וקטורים מוסיף התמדה, מסננים, upsert, מחיקה ו־ANN מעל מה ש־numpy כבר עושה. בגדלים
  קטנים המהירות אינה הסיבה.
- אוצר מילים: אוסף, מזהה, וקטור, מסמך, מטא־נתונים, מרחק. Chroma מחזירה מרחק קוסינוס, 1 פחות
  הדמיון.
- Chroma: לקוח מתמיד, `get_or_create_collection` עם `hnsw:space=cosine`, `upsert`, `query` עם
  `where`, תאריכים כמספרים, `n_results` לא מעל הגודל, וקטורים שלנו.
- שם המודל במטא־נתונים של האוסף; המאגר מסרב לערבב; החלפת מודל היא אינדוקס מחדש או אוסף חדש
  עם גרסה.
- מבחן „האם numpy מספיק?” לפני כל תלות. בפרויקט: numpy ליום, Chroma לזיכרון.
- מסנן אינו הרשאה; המסמך והווקטור רגישים כמו המקור; שימור הוא מחיקה לפי תאריך.

## מונחים לזכור

| מונח בעברית | באנגלית | במשפט אחד |
| --- | --- | --- |
| מאגר וקטורים | vector database | אינדקס שכנים קרובים עם התמדה, מסננים ועדכונים |
| אוסף | collection | טבלה של וקטורים עם מודל אחד ומרחק אחד |
| מטא־נתונים | metadata | מילון שטוח לכל פריט, לסינון |
| upsert | upsert | הוספה או החלפה לפי מזהה; הרצה חוזרת בטוחה |
| מרחק קוסינוס | cosine distance | 1 פחות דמיון קוסינוס; 0 זהה |
| אינדוקס מחדש | reindex | חישוב כל הווקטורים מחדש אחרי שינוי מודל |
| מאגר מוטמע | embedded database | ספרייה שכותבת לתיקייה, בלי שרת |
| שימור | retention | כמה זמן שומרים; מחיקה לפי תאריך |

## טעויות נפוצות

- **לבחור מאגר לפני לבדוק אם numpy מספיק.** תלות, תפעול וקוד, בשביל 5,000 וקטורים.
- **לשכוח `hnsw:space=cosine`.** ברירת המחדל היא L2, והמרחקים לא מה שציפית.
- **תאריכים כמחרוזות במטא־נתונים.** `$gte` נכשל; מספר yyyymmdd עובד.
- **לערבב מודלים באוסף.** תוצאות סבירות למראה ושגויות. שם המודל במטא־נתונים, בדיקה בפתיחה.
- **לתת למאגר לשכן בעצמו בלי כוונה.** מודל אחר, בלי מטמון, הורדה בפעם הראשונה.
- **לחשוב שמסנן הוא הרשאה.** שאילתה אחת ששכחה אותו חושפת הכול.

## שאלות ראיון

1. **מתי צריך מאגר וקטורים ומתי לא?** כשצריך התמדה, מסננים לפני החיפוש, עדכונים לפי מזהה,
   כמה תהליכים, או יותר ממאות אלפי וקטורים. אחרת מטריצת numpy וסריקה מלאה פשוטות ומהירות
   יותר. בפרויקט שלי השתמשתי בשניהם, לפי המבחן הזה.
2. **Chroma מול pgvector מול Qdrant?** Chroma: מוטמע, אפס תפעול, לפרויקטים קטנים. pgvector: כשיש
   כבר Postgres, וקטורים ליד הנתונים עם טרנזקציות והרשאות. Qdrant ודומיו: שרת ייעודי לגדלים
   ומסננים כבדים.
3. **מה קורה כשמחליפים מודל שיכון?** כל הווקטורים חסרי משמעות מול החדשים. שומרים את שם המודל
   במטא־נתונים של האוסף, מסרבים לכתוב כשהוא שונה, ובונים אוסף חדש (או מאנדקסים מחדש) ומחליפים
   כשהוא מוכן.
4. **איך מטפלים בהרשאות במאגר וקטורים?** מסנן מטא־נתונים הוא לא אבטחה; הוא כלי שהקוד חייב
   להפעיל תמיד. אוכפים בקוד שעוטף את המאגר, או משתמשים במאגר עם הרשאות אמיתיות (Postgres), או
   מפרידים אוספים לפי דייר.
